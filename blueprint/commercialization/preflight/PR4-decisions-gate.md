## Overview

Phase 2 (license gate) needs a signed key to exist before its exit test can run — but the control plane doesn't until phase 3. This prerequisite closes that hole now, and defines the readiness gate the whole commercialization plan is gated on.

## Decision to resolve (recommendation included — ratify or override)

**License private-key custody:** offline mint CLI, `loom-admin licensemint` (separate binary or `loom admin` hidden subcommand, never shipped to non-maintainers): reads key file from `~/.loom-admin/license.key` (0600, Ed25519, generated by `loom-admin keygen`), emits license keys with `--org --tier --seats --expires`. CP issuance at phase 6 calls the *same minting function*, not a parallel one — one mint path forever.

Why: unblocks phase 2's exit test with a 100-line CLI; matches the signed-offline-key practice (GitLab/Qarote/Keyforge precedent already cited in the plan); one mint codepath reused later.

## Implementation plan

1. `crates/loom-cli/src/commands/admin.rs` (or a `loom-admin` bin in loom-cli) — `keygen`, `licensemint` subcommands reusing signing helpers from `loom-hooks::signing` / `loom-core::plugin_registry` patterns (same verify/keygen, one more user of it).
2. Tests: mint → the exact verify function from the phase-2 spec (`loom-core::License::verify`) accepts; bad key file → refuse; wrong flag combos → refuse. Key file mode 0600 asserted.
3. Ship in release binaries but behind a clear maintainer doc line ("license minting is the vendor's key, customers get keys from the vendor") — no support surface, no docs page for end users.
